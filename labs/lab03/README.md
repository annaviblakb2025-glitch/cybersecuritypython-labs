# Лабораторна робота №3. Web API на FastAPI та SQLite

**Варіант 6: облік подій поштової безпеки.**

Навчальний сервіс зберігає підсумки перевірки повідомлень. Один запис описує спостереження: скільки подій певного типу виявлено за навчальний інтервал.

## Предметна область

| Поле | Значення |
|---|---|
| Категорії (`categories`) | `phishing`, `malicious_attachment`, `spam` |
| Запис (`records`) | `id`, `code`, `title`, `category_id`, `value`, `status` |
| `value` | кількість виявлених подій у спостереженні (ціле число, `>= 0`) |
| Одиниця виміру | `events` |
| Поріг | `10`|
| `status` | `new`, `in_progress`, `done` (стан опрацювання спостереження) |
| Назва запису | `Спостереження пошти NN`, код у форматі `V06-NN` |

Зв'язок між таблицями: **«один до багатьох»** (одна категорія містить багато записів). Видалити категорію із записами не можна (`ON DELETE RESTRICT`).

Усі дані навчальні й не описують реальну інфраструктуру.

## Структура

```
labs/lab03/
├── __init__.py
├── main.py          # FastAPI-застосунок, lifespan, обробники помилок
├── database.py      # З'єднання SQLite та виконання schema.sql
├── schema.sql       # Готова схема (варіант 6)
├── repository.py    # Параметризовані SQL-запити
├── schemas.py       # Pydantic-моделі запитів і відповідей
├── config.py        # Предметна область, одиниця виміру, поріг
├── seed.py          # Початкове заповнення бази з seed.json
├── routers/
│   ├── __init__.py
│   ├── categories.py
│   └── records.py
├── data/
│   ├── seed.json    # Навчальні дані (у Git)
│   └── lab3.sqlite3 # Створюється програмою (не в Git)
└── README.md
```

Розподіл відповідальності: маршрути приймають запит і формують відповідь, SQL лежить лише в `repository.py`, моделі лише в `schemas.py`. Модуль `repository.py` не залежить від FastAPI, а винятки SQLite перетворюються на HTTP-помилки в `main.py`.

## Встановлення

Усі команди виконуються з **кореня репозиторію** у віртуальному середовищі (Python 3.10 або новіший).

```bash
pip install -r requirements.txt
```

Потрібні пакети цієї роботи: `fastapi`, `uvicorn`, `pydantic` (версії 2.x) і `ruff`. Роботу з базою виконано без ORM, безпосередньо через `sqlite3`.

## Початкове заповнення бази

```bash
python -m labs.lab03.seed
```

Команда створює таблиці (якщо їх немає) та в **одній транзакції** додає 3 категорії і 8 записів із `data/seed.json`. Якщо дані некоректні або порушують обмеження, усі зміни скасовуються з повідомленням.

Повторний запуск на непорожній базі нічого не змінює і виводить `База вже містить дані. Зміни не внесено.`

Щоб почати з чистої бази, треба зупинити сервер і видалити файл `labs/lab03/data/lab3.sqlite3`, потім знову виконай seed.

## Запуск API

```bash
uvicorn labs.lab03.main:app --reload --host 127.0.0.1 --port 8000
```

Режим `--reload` призначений лише для розроблення. Під час запуску створюються відсутні таблиці, але дані не перезаписуються і база автоматично не заповнюється.

- Swagger UI: <http://127.0.0.1:8000/docs>
- OpenAPI-схема: <http://127.0.0.1:8000/openapi.json>

## Маршрути

| Метод і шлях | Призначення | Успіх |
|---|---|---|
| `GET /ping` | Перевірка доступності | 200, `{"status": "ok"}` |
| `GET /student` | Дані студента (`student_name`, `group_name`, `variant_number`) | 200 |
| `GET /categories` | Список категорій за зростанням `id` | 200 |
| `POST /categories` | Створити категорію | 201 |
| `DELETE /categories/{category_id}` | Видалити порожню категорію | 204 |
| `GET /records` | Список записів із фільтрами | 200 |
| `GET /records/{record_id}` | Один запис | 200 |
| `POST /records` | Створити запис | 201 |
| `PUT /records/{record_id}` | Повна заміна змінюваних полів | 200 |
| `DELETE /records/{record_id}` | Видалити запис | 204 |
| `POST /records/bulk` | Пакетне створення (1-100 записів), атомарно | 201 |

### Параметри `GET /records`

| Параметр | Обмеження | Дія |
|---|---|---|
| `category_id` | `int > 0` | лише записи категорії |
| `status` | `new`, `in_progress`, `done` | лише записи з цим статусом |
| `min_value` | `int >= 0` | `value >= min_value` |
| `q` | рядок 1-120 символів | буквальний підрядок у `title` (з урахуванням регістру) |
| `limit` | 1-100, типово 20 | максимальна кількість записів |
| `offset` | `>= 0`, типово 0 | скільки записів пропустити |

Кілька фільтрів поєднуються через `AND`. Результати завжди відсортовані за `id` за зростанням. Якщо збігів немає, повертається порожній список.

### Коди помилок

| Код | Коли |
|---|---|
| 404 | запис або категорія не існують (зокрема у `POST`, `PUT` і пакеті для неіснуючої категорії) |
| 409 | дублікат `code` або назви категорії; спроба видалити непорожню категорію |
| 422 | некоректні дані (наприклад, `value` від'ємне чи дробове, порожній `title`, недозволений `status`, `limit=0`) |
| 500 | неочікувана помилка бази; деталі пишуться в журнал, клієнт їх не бачить |

## Приклади запитів

Команди для Bash. У Windows ті самі запити зручно виконати через Swagger UI.

```bash
# Перевірка доступності
curl -i "http://127.0.0.1:8000/ping"

# Фільтри: категорія 1 і статус new
curl -i "http://127.0.0.1:8000/records?category_id=1&status=new&limit=5&offset=0"

# Створення запису (очікується 201)
curl -i -X POST "http://127.0.0.1:8000/records" \
  -H "Content-Type: application/json" \
  -d '{"code":"V06-TEST","title":"Навчальне спостереження","category_id":1,"value":7,"status":"new"}'

# Дробове значення (очікується 422)
curl -i -X POST "http://127.0.0.1:8000/records" \
  -H "Content-Type: application/json" \
  -d '{"code":"V06-BAD","title":"Тестовий запис","category_id":1,"value":1.5,"status":"new"}'

# Дублікат коду (очікується 409)
curl -i -X POST "http://127.0.0.1:8000/records" \
  -H "Content-Type: application/json" \
  -d '{"code":"V06-01","title":"Дублікат коду","category_id":1,"value":5,"status":"new"}'

# Скасування пакета: другий елемент має code із бази (очікується 409,
# запис V06-ROLLBACK не збережено)
curl -i -X POST "http://127.0.0.1:8000/records/bulk" \
  -H "Content-Type: application/json" \
  -d '[{"code":"V06-ROLLBACK","title":"ROLLBACK перший","category_id":1,"value":4,"status":"new"},{"code":"V06-01","title":"Дублікат коду","category_id":2,"value":5,"status":"new"}]'

# Перевірка, що V06-ROLLBACK відсутній (очікується [])
curl -i "http://127.0.0.1:8000/records?q=ROLLBACK&limit=100"
```

## Захист даних і цілісність

- **Параметризовані запити:** усі значення передаються через `?`, тому SQL-ін'єкція неможлива. Пошук `q` працює через `instr(title, ?) > 0`, символи `%` і `_` шаблонами не є.
- **Транзакції:** змінювальні операції виконуються в `with connection:` (успіх підтверджується, помилка скасовується), а пакетне додавання записів іде однією транзакцією без окремого `commit()` для кожного елемента.
- **Обмеження бази:** `PRIMARY KEY`, `FOREIGN KEY` (`PRAGMA foreign_keys = ON` для кожного з'єднання), `UNIQUE`, `NOT NULL` і `CHECK`.
- **Перевірка вхідних даних:** Pydantic (`extra="forbid"`, межі довжини, `value: int >= 0`, статус із визначеного набору).
- З'єднання відкривається й закривається всередині кожної операції, глобального з'єднання немає.
